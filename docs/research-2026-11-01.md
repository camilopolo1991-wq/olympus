# Olympus: research for the Pantheon front end. 2026-11-01, the chair, four research agents

Ask (Fate, 2026-11-01): a pixel-art front end where Olympus holds the main gods, the Forge has its island, every new god gets a domain, the lesser gods (the loop roles) are seen working, and stats and progress show. Deep research, multi-agent. This file is the result; the mockup page "Olympus: the Pantheon at work" is the visual spec.

## 1. Verdict

Build our own thin app, do not adopt an office simulator. Three layers:
- Feed: the record's step log is the single truth (append-only, monotonic, one line per step, scan-gated at every commit). A local server tails it by byte offset and serves it as Server-Sent Events, every line passed through the kit's own redactor module before it leaves the process. Second step, optional and gated: Claude Code hooks post sub-agent start and stop to the same server for live motion between log lines. Third step, gated: one Hermes tile per bot from the profile's session summary table, read-only, never a message.
- Server: one Python standard-library script run by the Hermes venv interpreter by full path (python on PATH is the Store stub), on 127.0.0.1, static files plus /events. Poll 250 to 500 ms, seq ids by byte offset, replay the whole log on load, then animate new lines only.
- Renderer: Phaser 4 (MIT, one 345 KB script, pixelArt flag, Tiled JSON maps, animation manager, TypeScript types), stats panels as plain HTML beside the canvas. The mockup's Canvas 2D is the zero-dependency fallback and is already enough for one map and eight walkers.

Why own and not adopt: the six usable open-source office apps (all MIT, all active in 2026) draw one generic office with one character per session. Fate's map is a Pantheon with named seats and domains that grow per god; the map is the product. What is borrowed: the status vocabulary idle, reading, thinking, writing, waiting, success, error (agent-town), the provider interface idea (Pixel Agents), and the hook to POST to stream to pixels pattern (the best-known dashboard has no licence file, so its pattern is borrowed and its code is not).

## 2. The feed, measured on the box (zeus-research-record, 2026-11-01 00:4x Z)

- Step log: 1620 lines, 1618 on the grammar "- <UTC> <GOAL> <STEP> <KIND> <text>", first 2026-10-22T20:44:45Z, last 2026-11-01T00:37:52Z, monotonic. Kinds and counts: TRIPWIRE 396 (198 OPEN, 198 CLOSE), DISPATCH 313 (reviewer 157, writer 124, scout 32, auditor never), ROLLBACK 124, PASS 102, DONE 80, FAIL 59, COMMIT 54, INCIDENT 48, BLOCKED 38, START 29, RETURNED 29, NOISE 26, HELD 26, PUSH 21, NOTE 21, FINDING 15, PARTIAL 13, FAIL(n) 20, DEVIATION 10, DENIED 10, RULING 8, OWNER-NOISE 8, LANDED 8, REPORT 6, GATE 6, CLOSED 5, NEEDS-DECISION 4, LANDED-PARTIAL 4, CORRECTION 4, ANSWERED 4, and about 45 irregular lines a parser must tolerate as plain notes.
- Rate: busiest minute 10 lines, busiest second 2, 1-second resolution. A 1 to 2 second poll by byte offset catches every line; 30 seconds when no goal runs.
- Goals by line count: KIT-02 403, ZEUS-01 207, KIT-05 175, BRAIN-04 173, KIT-04 167, KIT-03 153, STRUCT-01 148, GITHUB-01 118, BRAIN-01 57, KIT-06 9 (at the time), RECORD-01 7.
- Beside the log: plan.md per goal (table T, task, surface, done when, owner, status; a Live block with goal, status, window, step, branch, retries, gate), STATE.md (sections 0 to 5), report.md (Lead, Criteria, Proposed cards, Incidents, Numbers, Commits), 69 dispatch run logs named GOAL.TS.log and GOAL.audit.TS.log (mtime only, never content), 115 brain notes plus the zeus and shared folders.
- Gods: two Hermes profiles today, hephaestus (The Forge Master) and zeus (The Chair), title under ui_meta in profile.yaml. Lesser gods: the five agent files in the kit.
- Entity model: god = profile; lesser god = role, working from its DISPATCH until RETURNED, DONE, PASS or FAIL on the same step; goal from START, HELD, CLOSED; task from DISPATCH, RETURNED, PASS, FAIL(n), BLOCKED, PARTIAL, LANDED; window from TRIPWIRE OPEN and CLOSE; incident from INCIDENT, DENIED, DEVIATION, NOISE, OWNER-NOISE, ROLLBACK; commit from COMMIT, LANDED, PUSH; decision from GATE, NEEDS-DECISION, RULING, DECISION, FINDING, CORRECTION, REPORT.
- A guard note: the read-only agent could not list the goals folder (a scout lists only its own evidence); the dashboard server runs outside the loop's hooks, under Fate's word, read-only.

## 3. Live signals beyond the log (web agent, official docs read 2026-10-31)

- Claude Code hooks: every event carries session_id, cwd and, inside a sub-agent, agent_id and agent_type (the agent file's name, so loop-scout or zeus-research-box). Events worth a dashboard: SessionStart, SubagentStart, SubagentStop (with the agent type), PreToolUse and PostToolUse (tool name, duration), Stop, Notification (permission prompts), SessionEnd. A hook of type http posts the JSON to a local URL; a command hook with async true never blocks. Adding either is a settings.json edit, Fate's gate.
- Telemetry: CLAUDE_CODE_ENABLE_TELEMETRY=1 with an OTLP exporter to a local receiver on 4318 gives tokens, cost per model and per agent name, tool results with durations. Prometheus exporter alternative on 9464. Keep tool details and prompts off (default); filter the user attributes.
- Hermes: each profile keeps state.db in WAL mode, opened read-only by Hermes's own dashboard; the sessions table carries source, model, tokens, cost, tool_call_count, started and ended. The messages table holds chat text and is never read by the front end. Hermes's own local dashboard on 9119 exposes /api/sessions and /api/status. Reading state.db is Fate's gate (the loop's standing rule names state databases in the secret class).

## 4. Engines and art (web agent, registry and official pages 2026-10-31)

Engines: Phaser 4.2 (MIT, pixelArt flag, Tiled JSON, animations, TS types, monthly releases) recommended; Excalibur 0.32 (BSD-2) if LDtk maps are wanted; PixiJS 8 only with a hand-written tilemap layer; Kaplay has no map import; Godot web export rejected (size, server headers, no HTML overlay); Canvas 2D is the zero-dependency fallback and the mockup proves it carries the scene.

Art, CC0 or CC-BY only: Classical Temple Tiles and Classical Ruin Tiles by surt (CC0, 16 px, the only CC0 Greek set found) for Olympus; Kenney Tiny Town (CC0, 16 px) for land, water edges, trees, houses; Kenney Tiny Dungeon and Roguelike Characters (CC0, 16 px, static frames) or 0x72 DungeonTileset II (CC0, 4-frame run cycles) for the lesser gods; Sunset Temple Tiles (CC-BY 3.0 / CC0, 32 px) as an alternative; the LPC Greek architecture set only under share-alike (fine in a public repo with a CREDITS file). No CC0 forge, anvil, cloud or island pack exists: compose Tiny Town water and land with the temple tiles and draw the anvil and the smoke by hand, one tile each. Not usable: Sprout Lands free tier (non-commercial), Cute Fantasy (paid, per buyer).

## 5. The agent-office landscape (web agent, READMEs and GitHub API 2026-10-31)

Usable, all MIT, all pushed in 2026: agent-town (rafapetter; zero-dependency Canvas library, statuses by API, bridge from hooks to WebSocket; procedural art), Pixel Agents (office app with a provider interface and a layout editor), agent-visualiser (OTLP replay, CC0 art bundled), Agent Virtual Office (SSE, fixed eight roles), Claude-Office (isometric, signed hook events), agent-office (parsers per agent). Rejected: AI Town and the Stanford generative-agents demo own their state and run their own agent loops; WorkAdventure is AGPL plus Commons Clause and built for humans; several others carry no licence.

## 6. Build plan, OLYMPUS-01, for the Forge, in the pantheon repository after PANTHEON-01

Surface: pantheon/olympus/ with server.py, index.html, the Phaser script vendored, maps/ (Tiled JSON), assets/ with a CREDITS file naming every pack and licence, and tests/rows for the parser.
- C1 the feed: server.py serves static files and /events, tails the step log by byte offset, replays on connect, passes every line through the kit's redactor module, polls 500 ms, drops to 30 s when no goal runs. Rows: a fixture log with a planted name is served redacted; a truncated file resets the offset; seq ids resume after reconnect.
- C2 the parser: the entity model of section 2 in one browser module, tolerant of irregular lines. Rows: the real step log's kind counts reproduced from the fixture copy; every goal id reaches a terminal state; FAIL(n) retries counted.
- C3 the map: Tiled JSON, Olympus with one temple per seat (built or greyed), the Forge island with five huts, the record house, the tripwire board, a pier for the Messenger; a domain is one more Tiled layer per god, added by a later card. Rows: the map loads, every named object exists.
- C4 the figures: five lesser gods with walk cycles, three main gods standing at their temples, the Messenger on the pier; motion driven by the parser's states. Rows: a scripted event sequence ends with every figure at the expected tile.
- C5 the panels: goal, status, window, counters by line kind, task table from plan.md, step-log ticker, KIT and seat progress. Rows: counters equal the parser's counts on the fixture.
- C6 (gated, Fate's settings edit): http hooks for SubagentStart and SubagentStop posting to server.py, lesser gods move on the hook before the log line lands.
- C7 (gated, Fate's state.db grant): one tile per Hermes bot from the sessions table, model, tokens, cost, tool calls, read-only, messages never read.
- C8 (later): the telemetry receiver for cost per agent name and the plan-usage tile.
Acceptance: the page runs on 127.0.0.1 from one command, shows KIT-06's run from its first line, moves on a new line within two seconds, serves no name and no secret (a planted-name row), and the visual check is Fate's.
